# DECISIONS

1. **Source data:** `data/raw/ad_nprm.xlsx` copied from Downloads; SHA-256 `3bc255f5f790b3adf41b8b70525dd1867310820801ac960fedf9b3ddc2fb1fd0`. Original untouched.
2. **UI: FastAPI + static HTML instead of Streamlit.** Streamlit needs `pyarrow`, which has no wheel for this ARM64 Python 3.13 (build failed); a binary-only install pulled streamlit 0.8, which is broken. FastAPI and uvicorn already work.
3. **LLM:** Anthropic (`claude-haiku-5-5` verified working). Used only for (a) query-parser fallback, (b) the LLM-only baseline. Never for applicability, revision status or answer facts. Ramith approved use.
4. **Dev dependencies installed:** bm25s, anthropic, uvicorn.

5. **Test set v1 FROZEN 2026-10-31 11:12 SGT.** `eval/testset_v1.jsonl`, 40 questions (10 lookup, 12 applicability, 6 revision, 12 refuse; 10 dev / 30 test). SHA-256 `3097beda9d7118d0cfbaf90ffb50f4945287fc1705cc426b56fa2f8ff9ed609b`. No edits after this; any change becomes v2 and v1 results are still reported.
   - **Authorship caveat (must appear in README):** written by the AI coding assistant that also builds the system, not by an independent person, because the team is one human with three hours. Mitigations: labels were derived from the spreadsheet and the Federal Register full text (not from system output), written before any system code existed; the 30 `test` questions are never used for tuning; Ramith spot-checks a sample of labels (target 10) before submission. Single annotator, 40 questions: too small for tight confidence intervals.
   - **Doc ID convention:** FR document number (e.g. `2026-20543`); rows with no resolved FR doc number use `docket@YYYY-MM-DD`.
   - **Reason-code semantics:** `CERT_DATE_BEFORE_CUTOFF` = CofA on or before the cutoff (in scope); `CERT_DATE_AFTER_CUTOFF` = after (out of scope).
   - **Codes added beyond the control prompt:** `EXCLUSION_UNVERIFIABLE` (AD excludes airplanes meeting a maintenance-programme condition the user didn't state), `INSUFFICIENT_EVIDENCE` as a refusal code.
   - **Refusal scoring:** refusal precision/recall count any refusal; refusal-code accuracy is reported separately.
   - Where a model appears in several NPRMs, questions are anchored by docket, superseded AD number, or bulletin so the gold doc is unique. The gold doc for a revised docket is the **latest** entry.

6. **Doc-number resolution widened.** Link regex now handles `/documents/YYYY/MM/DD/N`, `/documents/N`, `/d/N`, `/a/N` and `R1-YYYY-N` forms: 237 rows resolve (229 unique FR documents), up from 216 in scoping. All 229 fetched, 0 errors.

Used as text source `embedded` (some cells had literal `\n`/`\t`, normalised once). Full-text coverage: fr_text 237 + embedded 169 = **406/431 (94.2%)**; 25 rows summary_only.
8. **Three source formats parsed** (modern lettered, old lettered, oldest unlettered/inline "Applicability:"). Applicability section found in 304 rows; 65 are withdrawal notices; 37 full-text rows lack an applicability section (extension/correction notices or partial text).
9. **Full-corpus applicability patterns** (regex hits on 304 parsed sections, see `data/processed/coverage_report.md`): model list 96%, "all" 35%, EASA/TCCA/ANAC AD 11%, "as identified in" 24%, part number 10%, serial number 18% (includes "all serial numbers" phrasing), "except" 3%, CofA date cutoff 1%. These correct the 30-document sample from scoping (serial 3%).
10. `data/processed/docs.jsonl` (full text) is git-ignored; regenerate with `python src/ingest.py && python src/build_corpus.py && python src/coverage_patterns.py`.

11. **Phase 2 engine and extractor (Gate 2 passed 11:28).** `src/extract.py` (rules only), `src/applicability.py` (pure functions, fixed order: Part 39 -> withdrawn -> text -> model -> part number -> certificate date -> serial -> exclusions -> other configuration clauses -> external documents -> APPLIES), `src/revisions.py` (docket graph, comment extensions never replace the proposal they extend, R1 dockets folded into base).
12. **Restraint rule applied after the audit** (serial extraction was below the 90% threshold): any serial wording beyond a clean range, any part-number list that is not clean tokens, and any configuration clause the tool does not evaluate -> `CANNOT_DETERMINE / AMBIGUOUS_SCOPE` with the clause quoted. Added reason code `INPUT_MISSING_MODEL`.
13. **Test-split discipline:** the 30 `test` questions have not been run. Phase 2 used only dev items (A01, A03, A07, R01, R05) plus unit tests on documents that are not test items where possible (some engine unit tests reuse documents that also appear in test questions, with expectations read from the source text).
14. **Extraction audit** is single-reviewer and not independent; see `eval/results/extraction_audit.md` for all four rounds, including the failures.

15. **Phase 3 built (Gate 3 passed 11:44).** `src/query_parse.py` (rules, no LLM), `src/retrieve.py` (4,263 section-aware chunks, bm25s, metadata filter applied before ranking), `src/answer.py` (extractive cards, typed refusals, quote verifier), `src/api.py` + `ui/index.html` (FastAPI + single page, three panels). UI is FastAPI + static HTML, not Streamlit (see #2). `C.rec` has 423 unique doc_ids for 431 rows because 8 rows share an FR document number (multi-docket notices).
16. **Overfitting controls and their limits.** (a) Test split frozen by hash; `eval/run_eval.py` refuses `--split test|all` without `--final`, refuses if the test-set hash changed, logs every test run to `eval/results/test_run_log.txt`, and records the git commit. (b) Rule-based, so no model weights to overfit, but rules ARE corpus-specific wording rules. (c) Two generalisation sets of ad-hoc queries with different phrasing, scored on FIRST pass before any fix: set A 21/24 (87.5%), set B 13/15 (86.7%). Failures were fixed afterwards as general changes (no special cases); the later 24/24 and 15/15 are contaminated and must not be quoted as generalisation. (d) Extraction audit rounds used fresh seeds; round D untouched. **Limits to disclose:** I wrote the test set and know its content, and I read the documents behind it, so the test split is not blind; refusal rules were written from general principles but by someone who had seen the test wording, so the refusal category is likely optimistic. Dev split is 10 questions only, so nothing tuned on it is reliable. `T_LOW = 8.0` (BM25 floor) was set by inspecting score ranges (relevant 15-21, irrelevant 4-9) and checked on dev + ad-hoc only; short entity queries bypass it when a rare corpus term matches (`rare_query_tokens`).
17. **Refusal logic** is rule-based and ordered: off-topic -> airworthiness/safety judgement -> pre-2001 -> question about an external document -> final-rule question -> unknown docket/AD -> not Part 39 -> ambiguous -> unknown entity word -> contradictory make/model -> low retrieval evidence -> value asked for but number absent from text.
18. **No generated text.** Answers are verbatim spans (re-verified against the stored source before returning; `dropped_quotes` is reported) plus fixed template labels. The Anthropic key is not used anywhere in the answer path.

20. **First-pass blind results and what they forced (honest account).** On B1/B2 the first pass (system `4c340ae`, saved as `eval/results/FIRSTPASS_blind_B1_B2_full.json`) was: B1 verdict accuracy 82.6% (19/23); B2 lookup 91.7%, free-text applicability 25% (2/8), revision 100%, refusal recall 90%, refusal-code accuracy 60%. The dev split had been 100%, so the system had overfit its development material. Causes (all general): model chosen from the AD description instead of the user's aircraft; make chosen by rule order not sentence position; candidates restricted to documents naming the model (hid DOES_NOT_APPLY cases); partial model matches ("BK117" inside "BK117 D-2"); list expansion broke on a dropped dash; family-prefix lists ("Trent 768-60, 772-60, 772B-60"); serial lists not parsed; "Falcon 2000" read as the year 2000; foreign-AD content questions. Fixed as general changes (system commit `d5cf2b2`). Re-running B1/B2 after the fixes (B1 95.7%, B2 applicability 75%) is CONTAMINATED (selected on those sets) and is not a generalisation estimate.
